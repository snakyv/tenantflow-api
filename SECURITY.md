# Security Policy

## Supported versions

Security fixes are applied to the latest release on the `main` branch.

## Reporting a vulnerability

Please do not open a public issue for a suspected vulnerability. Use GitHub's private vulnerability reporting when enabled, or contact the repository owner privately.

Do not include real credentials, access tokens, refresh tokens, Stripe secrets, customer data, or production payloads in a report.

## Security boundaries demonstrated by this project

TenantFlow treats PostgreSQL as the durable source of truth and applies tenant scoping to organization-owned queries. Authentication uses short-lived JWT access tokens, Argon2 password hashing and fingerprinted rotating refresh tokens. Authorization uses an explicit RBAC matrix.

Additional boundaries include:

- production startup rejects default, short or reused JWT/webhook-encryption secrets;
- request IDs are length/character constrained before being reflected into logs and responses;
- common defensive response headers are added by middleware;
- Redis rate limiting is distributed rather than process-local;
- webhook signing secrets are encrypted at rest and outbound targets are restricted to public addresses in production to reduce SSRF exposure;
- Stripe webhook signatures are verified and Stripe event IDs are deduplicated transactionally;
- uploaded object keys are generated by the server and tenant-scoped rather than derived directly from user-controlled paths;
- secrets and authorization headers are excluded from application logging by design.

## Local-development exception

`.env.example` enables `WEBHOOK_ALLOW_PRIVATE_TARGETS=true` so a developer can test callbacks against local services. **Production mode refuses to start with that setting enabled.**
